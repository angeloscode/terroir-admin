# Terroir — сайт и админка на одном домене

Публичный сайт на **Astro** и админ-панель на **Next.js** работают на одном домене и поднимаются одной командой через Docker Compose.

ПРЕДУПРЕЖДЕНИЕ!!!
я не заморачивался с обновлением витрины товаров изменениями или добавлениями поинтов на карте и тд, я сделал базу базовую что требует лендинг, добавил мини метрику просмотров


| Адрес | Что открывается |
|---|---|
| `http://localhost/` | сайт (Astro, статика) |
| `http://localhost/admin` | админка (Next.js, вход по email и паролю) |

## Быстрый старт

Нужен только Docker с Compose v2.

```bash
# 1. Создать .env (секреты генерируются автоматически)
cat > .env <<EOF
SITE_ADDRESS=:80
PUBLIC_SITE_URL=http://localhost
HTTP_PORT=80
HTTPS_PORT=443
AUTH_SECRET=$(openssl rand -base64 32)
POSTGRES_PASSWORD=$(openssl rand -hex 16)
EOF

# 2. Собрать и запустить (первая сборка идёт несколько минут)
docker compose up -d --build

# 3. Дождаться статуса healthy у обоих сервисов
docker compose ps

# 4. Создать администратора
docker compose exec app create-admin reviewer@example.com 'reviewer123' 'Ревьюер'
```

Затем откройте http://localhost/admin и войдите под созданной учётной записью.

> Если порт 80 занят, укажите в `.env` `HTTP_PORT=8080` и `PUBLIC_SITE_URL=http://localhost:8080`, затем выполните `docker compose up -d`.

### Управление

```bash
docker compose logs -f app       # логи Caddy и Next.js
docker compose up -d --build     # пересобрать после изменений
docker compose down              # остановить, данные БД сохранятся
docker compose down -v           # остановить и удалить данные БД
```

## Архитектура

```
                 ┌──────────────────── контейнер app ────────────────────┐
 :80 / :443  →   │  Caddy ─┬─ /admin, /admin/*  →  Next.js (127.0.0.1:3000)  │ ──→  контейнер db
                 │         └─ всё остальное     →  /srv/site (статика Astro) │       (PostgreSQL 17)
                 └───────────────────────────────────────────────────────┘
```

- **Один контейнер `app` на весь трафик.** Caddy сам раздаёт статику Astro и проксирует `/admin` в Next.js. Next слушает только `127.0.0.1`, снаружи он недоступен. Процессами управляют `tini` и [entrypoint.sh](docker/entrypoint.sh): если падает Caddy или Next, контейнер завершается, и Docker перезапускает его целиком.
- **PostgreSQL вынесен в отдельный сервис.** Данные хранятся в volume, порт наружу не открыт. Держать БД в одном контейнере с приложением — известный антипаттерн: данные легко потерять при пересборке, обновлять неудобно.
- **Миграции** Prisma (`migrate deploy`) применяются автоматически при старте `app`. Отключается через `RUN_MIGRATIONS=false`.
- **HTTPS.** Для прода достаточно задать `SITE_ADDRESS=example.com`: Caddy сам выпустит и продлит сертификат Let's Encrypt. Сертификаты хранятся в volume `caddy_data`.

### Ключевые решения

| Решение | Почему |
|---|---|
| `basePath: "/admin"` в Next.js | Все пути админки, включая `/_next/*` и `/api/auth/*`, сразу живут под `/admin`. Прокси не срезает префикс, поэтому пути Astro и Next не пересекаются. |
| Auth.js: серверный `basePath` оставлен стандартным `/api/auth` | Next отдаёт route handler путь уже без `/admin`. Публичный путь `/admin/api/auth` передаётся клиенту через `SessionProvider` ([app/layout.tsx](terroir-admin/app/layout.tsx)). |
| `AUTH_URL` содержит только origin, без `/admin` | Из него Auth.js берёт хост для редиректов. Если добавить путь, Auth.js переопределит свой `basePath` и роутинг сломается. |
| Ссылки «На сайт» сделаны через `<a>`, а не `<Link>` | `next/link` добавил бы префикс `/admin`, а ссылка должна вести на корень Astro. |
| Next.js `output: "standalone"` | Минимальный рантайм без полного `node_modules`. |
| Скрипт `create-admin` вместо seed с зашитым паролем | Seed с паролем в коде для прода не годится. Скрипт одинаково работает в контейнере и локально. |

## Админка

Админка — минимальная основа для управления сайтом: вход, защищённая оболочка (сайдбар и шапка), главная страница с мини-аналитикой посещаемости и раздел «Вина» для витрины на сайте. Всё, что сайту не нужно, удалено (см. [ниже](#почему-админка-минимальная)).

- **Вход** — `/admin/login`: две колонки, слева форма (email и пароль), справа обложка. Валидация через zod и react-hook-form, ошибки показываются всплывающими уведомлениями.
- **Доступ только для роли `ADMIN`.** Проверка выполняется в двух местах:
  - при входе, в [auth.config.ts](terroir-admin/auth.config.ts): пользователь с другой ролью не авторизуется;
  - на каждом запросе, в [app/(dashboard)/layout.tsx](terroir-admin/app/(dashboard)/layout.tsx).
- **Актуальность сессии.** JWT-сессия на каждом запросе сверяется с БД ([auth.ts](terroir-admin/auth.ts)). Смена роли применяется сразу, удалённый пользователь сразу теряет доступ.
- **Мини-аналитика** на «Обзоре»: просмотры и посетители за сегодня и за 7 дней (со сравнением со вчера и с прошлой неделей), плюс график просмотров за 14 дней.
  - **Как собирается.** Сайт при загрузке страницы отправляет маячок `navigator.sendBeacon("/admin/api/track")` ([BaseLayout.astro](terroir-black-sea/src/layouts/BaseLayout.astro)). Обработчик — [app/api/track/route.ts](terroir-admin/app/api/track/route.ts).
  - **Приватность.** Cookie не используются, IP не хранится. Посетитель — это хеш от IP, User-Agent, даты и секрета; хеш меняется каждые сутки, поэтому посетитель уникален только в пределах дня.
  - **Фильтрация.** Боты отсеиваются по User-Agent. Query-строка и `#` из пути отбрасываются. Сутки считаются по Москве ([lib/analytics.ts](terroir-admin/lib/analytics.ts)).
  - **Ограничение.** Маячок работает только на общем домене (Docker). При раздельном `npm run dev` сайт и админка живут на разных портах, и просмотры не пишутся.
- **Вина** (`/admin/wines`) управляют витриной в секции «Коллекция вин» на сайте.
  - **Что можно:** список, добавление, редактирование и удаление вина, переключатель «Показывать на сайте».
  - **Поля:** все, что нужно вёрстке — название, цена, терруар (он же фильтр на сайте), цвет и сладость (из них собирается «Красное · сухое»), порядок на витрине, фото (JPEG/PNG/WebP до 5 МБ) и кадрирование фото.
  - **Превью.** В форме показывается превью карточки в пропорциях сайта.
  - **Стартовые данные.** Миграция переносит в БД 4 вина, которые раньше были зашиты в вёрстку.
  - **Где код:** Server Actions — [actions/wines.ts](terroir-admin/actions/wines.ts), общие справочники и формат — [lib/wines.ts](terroir-admin/lib/wines.ts).
- **Витрина на сайте берёт данные из хендлера** ([WineCollection.astro](terroir-black-sea/src/components/WineCollection.astro)).
  - **Загрузка.** После загрузки страницы скрипт запрашивает `GET /admin/api/wines` и перерисовывает карточки и фильтры. Фильтры строятся из терруаров, которые реально есть среди опубликованных вин.
  - **Запасной вариант.** В HTML остаются статичные карточки: они нужны для поисковиков, работы без JS и на случай недоступности API. Если данные совпадают со статикой, перерисовки нет, и страница не мигает.
  - **Безопасность.** Текст из БД вставляется только через `textContent`, поэтому данные не могут внедрить разметку.
- **Хендлеры для сайта** — публичные, без авторизации:

  | Маршрут | Что отдаёт |
  |---|---|
  | `GET /admin/api/wines` | опубликованные вина в порядке витрины, уже готовые к выводу (`price: "3 200 ₽"`, `style: "Красное · сухое"`), `Cache-Control: no-store` |
  | `GET /admin/api/wines/:id/image` | фото из БД; в URL есть `?v=<updatedAt>`, поэтому кэш на год |
  | `POST /admin/api/track` | маячок аналитики |
- **БД:** таблицы `users`, `page_views` и `wines` (Prisma). Вход по паролю и JWT-сессии не требуют таблиц OAuth и `PrismaAdapter`.
- **Стек:** Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS v4, shadcn/ui, Auth.js v5 (Credentials, JWT), Prisma 5, PostgreSQL.

### Почему админка минимальная

Сайт на Astro — статический одностраничный лендинг. У него нет корзины, заказов, клиентов, форм и аккаунтов посетителей. Поэтому из админки удалено всё, что под продукт не подходит:

- шаблон `dashboard-01` с демо-метриками выручки, графиком посетителей и таблицей документов;
- неиспользуемые shadcn-компоненты и хуки;
- OAuth-таблицы и `PrismaAdapter`;
- 32 npm-зависимости.

Вина уже вынесены в админку. Остальной контент пока зашит прямо в Astro-компонентах — это кандидаты на следующие разделы:

| Раздел | Где сейчас на сайте | Что там есть |
|---|---|---|
| Терруары | `Terroirs.astro`, `TerroirMap.astro` | описание, фото, контур на карте |
| Журнал | `Journal.astro` | фильмы, исследования, интервью |
| Контакты | `Footer.astro` | email для общих вопросов и для партнёров |

Их можно подключить по той же схеме, что и вина: таблица в БД, раздел в админке, публичный хендлер, а на сайте — статичный запасной вариант и подгрузка данных скриптом.

## Структура

```
.
├── compose.yml              # app + db
├── Dockerfile               # многоэтапная сборка: Astro → Next → рантайм с Caddy
├── docker/
│   ├── Caddyfile            # маршрутизация, заголовки безопасности, кэширование
│   └── entrypoint.sh        # миграции, запуск Next и Caddy
├── terroir-black-sea/       # сайт (Astro, static output)
└── terroir-admin/           # админка (Next.js)
    ├── app/(auth)/login/    # страница входа
    ├── app/(dashboard)/     # защищённый layout (сайдбар, шапка), главная, wines/
    ├── actions/wines.ts     # Server Actions: создание, правка, удаление вин
    ├── components/          # app-sidebar, nav-user, site-header, auth/, wines/, ui/ (shadcn)
    ├── auth.ts, auth.config.ts, proxy.ts   # Auth.js (proxy.ts — бывший middleware, Next 16)
    ├── app/api/             # хендлеры для сайта: wines, wines/[id]/image, track
    ├── lib/wines.ts         # справочники, форматирование, валидация, формат API
    ├── prisma/              # схема (users, page_views, wines) и миграции
    └── scripts/create-admin.mjs
```

## Локальная разработка (без Docker)

Требования: Node.js **≥ 22.12** (этого требует Astro 7; в Docker используется Node 24) и запущенный PostgreSQL.

```bash
# Админка → http://localhost:3000/admin
cd terroir-admin
cp .env.example .env   # указать DATABASE_URL и AUTH_SECRET (openssl rand -base64 32)
npm ci
npm run db:migrate
npm run admin:create -- admin@example.com 'admin12345' 'Администратор'
npm run dev

# Сайт → http://localhost:4321
cd terroir-black-sea
npm ci
npm run dev
```

## Известные ограничения

- Из контента в админке пока только вина. Терруары, журнал и контакты по-прежнему зашиты в вёрстку (см. [таблицу выше](#почему-админка-минимальная)).
- Витрина подгружает данные только на общем домене (Docker). При раздельном `npm run dev` показываются статичные карточки.
- Регистрации нет: учётные записи создаются командой `create-admin`.
- Во встроенном Caddy нет ограничения частоты запросов к логину. Для прода стоит собрать Caddy с плагином rate-limit или поставить такое ограничение на балансировщике.
